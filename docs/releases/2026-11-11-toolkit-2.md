# Toolkit 2

Toolkit 2 builds a Mendix app faster, and it proves more of what it built. It can report toolkit
bugs for you, with names and paths redacted. Existing projects change in a few places after sync;
see "What behaves differently".

"Toolkit 2" is a name for this batch of work, not a 2.0 milestone and not a version: the cut is an
ordinary run of dated releases. It spans two: `v2026.11.10`, already cut on master, and
`v2026.11.11`, which will carry the remaining Unreleased lines. Neither tag is published yet.
Upgrading is pull and sync, but a project that passed can turn red afterwards; see "What behaves
differently" (the section-wide coverage FAIL, journeys flipping to PENDING, and the persona
preflight can do it). See
[`docs/RELEASE-PROCESS.md`](../RELEASE-PROCESS.md) §6 and §8. Every line traces to
[`CHANGELOG.md`](../../CHANGELOG.md). Speed figures come from one run on one app each.

## What's new

1. **Pipeline modes.** Choose speed or rigour per project. `balanced` is the default;
   `high-speed` skips the per-row page check; `high-quality` keeps the earlier per-row journeys
   and checks (LOOK at 390 and 1280). Put `Pipeline mode: high-quality` in `PROJECT.md` to keep the old cadence. In the
   mode experiment, balanced took 3.25 min per row against 4.65 for high-quality (net of module
   close), high-speed 2.05, and no mode missed a defect.
2. **Speed core.** Re-runnability is proven by one `mxcli diff` (1.7 s) instead of a second gated
   exec (35 to 120 s). A hung journey is cut off after 120 s and named.
3. **Cheaper builds.** Each exec runs the lighter `mx check`; the full build runs at module
   close. `bin/doctor.sh --bench` times your machine.
4. **Persona preflight.** A journey batch that logs in as a missing user now fails before it
   starts, one line per persona (about 1 s), instead of each journey waiting about 100 s.
5. **Bug reports that file themselves.** See "Report a bug".
6. **More honest gates.** Stage 2 no longer trusts a requirements-driven BRD that calls itself
   "Clean"; Stage 3 fails an interaction model that leaves out a user task; a confirmed
   Marketplace "Buy" is checked against the model before the build; Stage 0 rejects a `_pending_`
   sign-off.
7. **Journeys do more.** Back, phone mode, offline and online, a GPS fix, a named grid row.
8. **Better unit tests.** Inputs come from each flow's decisions, and a committed row is read back
   from outside the test. `project-bin/rollback-scan.sh` (advisory) lists side effects a rollback
   will not undo.
9. **Flaky-network testing.** `project-tests/e2e/link-proxy.js` simulates latency, loss, outages
   and refusals; `exactly-once.js` flags a redelivered request. `project-bin/project-facts.sh`
   prints ports, roles and secret key names (never values).
10. **Learnings.** A workflow-called microflow returns nothing by default (STOP row 34); find
    constant usages with `search`; use `--skip-app-startup` when `mxcli test --local` hangs.
11. **Multi-app systems.** `bin/contract-check.sh` compares service contracts across apps.
12. **Fixes.** `doctor` names a project `./mxcli` built for another OS, and its timing check
    works on macOS; neither is run on a real Mac yet. The test-scratch libs signature is faster.

## Settings you can change

| Setting | Where | Effect |
|---|---|---|
| `Pipeline mode: high-speed`, `balanced` or `high-quality` | `PROJECT.md` | What runs per row and what waits for module close; no line means `balanced` |
| `UI polish: <N>% / <R> rounds` | `PROJECT.md` | Polish loop stop point |
| `Gate mode: full` | `PROJECT.md` or `MXTK_GATE_MODE=full` | A full build per exec instead of `mx check` |
| `JOURNEY_TIMEOUT_S` | environment | Default 120; `0` removes it |
| `Bug filing: auto` | `PROJECT.md` | Lets `--auto` file clean reports |

Earlier settings: [1.0 notes, section 2](v1.0.md#2-settings-you-control).

## What behaves differently

After `sync-project.sh`, an existing project will notice:

- **Cadence.** With no `Pipeline mode:` line the project is `balanced`: per row, the exec gate, one
  LOOK at 1280 of the changed page and one run of the journeys that reach it (about 1 min); unit
  tests and the full pre-push build wait for module close. sync prints one line when the line is missing.
- **Section-wide coverage claims now FAIL.** A plan row such as `F001/microflows/* (5)` claims a
  whole section at once. It FAILs Stage 4 and the coverage step of `verify-module.sh`, so a
  mid-build module can go red after sync. Remedy: split the claim per element, or record
  `Waived artifact coverage-ledger: <reason>`.
- **Modules with no real journeys run now read PENDING.** The journeys check used to count the
  summary file existing; now only a journeys row of PASS or FINDING counts. A module whose runtime
  was down or whose journeys were skipped flips from done to PENDING. Remedy: run the module's journeys
  (`project-bin/verify-module.sh <Module>`), or record a deliberate skip with
  `bin/gate-check.sh <project> --waive journeys/<Module> --reason "<why>"`.
- **Stage 1 reads extraction-quality files.** A file below threshold, with missing dimensions, or
  unparseable FAILs. With no file, the PASS line says quality was not scored. A triage naming auto
  mode as confirmer is a FAIL unless `Interview mode: auto`. Remedy for a quality FAIL you accept:
  `Waived artifact extraction-quality: <reason>` in `PROJECT.md`. At the exit code Stage 1 stays
  advisory.
- **Journey timeout.** Each journey stops after 120 s: a named FAIL ("journey TIMEOUT"), the rest
  INVALID, exit code 124. `JOURNEY_TIMEOUT_S=0` removes the limit.
- **Persona preflight can stop a module close.** A missing persona or role records a FAULT and the
  journeys do not start. Remedy: add the demo user
  (`create demo user '<name>' password '<pw>' (<UserRole>);`), or fix the journey's `persona`
  name (and `personaRole` if the role differs). If the check cannot measure (exit 2) it does not
  block.
- **Idempotence check.** `idempotence-check.sh` exits 1 on a script that cannot be re-run, 2 when
  it cannot tell.
- **Exit codes.** `exec.sh` returns 4 for "applied, gate passed, lint only" and 5 for "applied,
  unverified"; wrappers that test for 1 must be updated. `monkey.js` and `named-controls.js`
  return 2 for "not measured" (a FAULT row).
- **Stricter gates.** New FAILs at Stages 0, 2 and 3 and at build-ready (see item 6 above).
- **Stage 6 reads `docs/report.json`.** A failed check or aborted run is FAIL (exit 1, was PENDING
  3); faults only is PENDING, remedy: fix the harness, re-run; an unreadable report is FAIL; an
  empty one is PENDING; a stale one still passes with a warning.
- **Stage 4 coherence row.** Typed PROVE or BUILD in a plan with a Kind column is FAIL; type it
  HARNESS/RUN.
- **Bug filing.** `--auto` without a usable `gh` writes a bundle, not links, unless you declare a
  GitHub account with `--github-account` or `MXTK_GITHUB_ACCOUNT=1`.
- **Loosening a baseline** needs you to type `loosen` in your own terminal.

## How to upgrade

```bash
git -C ~/Mendix/mxcli-project-toolkit pull
~/Mendix/mxcli-project-toolkit/bin/sync-project.sh <project-root>
```

sync prints `Toolkit release: vYYYY.MM.DD` (or `vYYYY.MM.DD-N-g<sha>` when N commits past it). New
intake question Q15 (pipeline mode) is reported by sync;
`bin/sync-project.sh <project-root> --repair-intake` appends it to an untouched intake.

To go back: `git -C ~/Mendix/mxcli-project-toolkit checkout <previous-tag>`, then run sync again.
To return to the latest, `git checkout master`.

## Report a bug

Log a bug with `bin/file-bugs.sh --add`; home paths, names, emails, IPs, tokens and project,
module and entity names are redacted first, and a report that still looks unsafe is held back.
Then `Bug filing: auto` in `PROJECT.md` plus `--auto` files to GitHub with your own `gh` login;
`--links` prints pre-filled links; `--bundle` writes `toolkit-bugs-<date>.md` to mail to the
address on its first line (`MXTK_BUG_EMAIL`).

## Known limits

- Not yet run on Windows/Git Bash: pipeline modes, the journey timeout, persona preflight, bug
  filing, link-proxy, project-facts and rollback-scan. Their measurements are from Linux.
- `contract-check.sh` has not been run on a real multi-app system.
- The Marketplace "Buy" check has not been run against a real build with a Marketplace install.
