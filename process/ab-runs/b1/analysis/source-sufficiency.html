Contradictions — a human must choose

  • Fast-track auto-approval vs. manual-review-only08-booking-lifecycle.md §4.4 states a booking is auto-approved when the berth is free for the whole stay and the vessel is under 120m LOA. 15-officer-review-process.md §11.4 states 'There is no automatic approval; every booking request is reviewed by a berth officer before it can become Approved.' Both are Revision 7 (current). Resolved ASSUMED in this unattended run in favour of §11.4 (the more explicit, unambiguous statement) — the fast-track rule is treated as superseded/stale content, not built. Cost if wrong: officers manually approve cases that could have auto-approved — a conservative, low-risk direction to be wrong in.
  • Dangerous-goods approval gate vs. inspection-scheduling precondition22-inspection-scheduling.md §18.1 says an inspector schedules an inspection against an Approved booking (approval precedes scheduling, general case). §18.2 says a Dangerous Goods booking cannot be Approved until an inspection has been scheduled (scheduling precedes approval, for DG). Resolved ASSUMED in this unattended run as a DG-specific carve-out on the approval gate, not a true contradiction: for DG cargo the officer schedules the inspection while the booking is Under Review, then approves once it is scheduled. Cost if wrong: DG booking microflow's schedule/approve ordering would need to be reversed at Stage 5 — a single microflow, low cost.

Shape-changing gaps — silences that redesign the model, not details that fill it in

  • Cargo manifest PDF attachment on a booking request — never promoted to a chapterworkshop-notes.md session 2: 'Agents must be able to attach the cargo manifest as a PDF to a booking request' — attachment size limit explicitly 'not decided'. Absent from all 8 revisions of the numbered chapters. This changes the BookingRequest shape (a file association) if adopted. Resolved ASSUMED deferred/out-of-scope for the Stage 2 BRD in this unattended run — ADR-007 treats the chapters, not the raw workshop notes, as where requirements are settled, and 7 revisions have not adopted it. Cost if wrong: a real feature is missing from Stage 3 architecture and needs a retrofit (one file-association entity + one page control).
  • 'Last five bookings of the same vessel' on the officer review screen — never promoted to a chapterworkshop-notes.md session 3: 'The review screen must show the last five bookings of the same vessel.' Absent from 21-officer-review-screen.md and every other chapter. Changes the review screen's data requirements (a vessel-history sub-list) if adopted. Resolved ASSUMED deferred/out-of-scope in this unattended run, same reasoning as above. Cost if wrong: one extra list widget on one page at Stage 5, low cost.
