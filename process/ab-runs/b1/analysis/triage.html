Recommended Scope Subset

A slice is an ordering, not an exclusion — the whole documented application is in scope for this project. Recommended build order (by dependency: master data before the things that reference it, booking before review, review before money/inspection):

1. Vessel & agent registry, Berth & terminal master data -> Ready-equivalent (Manual/first) -> yes -> everything else references these 2. Booking lifecycle & request form -> Manual -> yes -> the core transaction; blocks review 3. Officer review & approval -> Manual -> yes -> depends on (2) 4. Inspections & departure clearance -> Manual -> yes -> depends on (3) for Approved bookings, and the fit/DG rules 5. Tariffs, fees & invoicing -> Manual -> yes -> depends on (2)+(3) for a Completed booking to invoice 6. Notifications, Audit & compliance -> Manual -> yes -> cross-cutting, wired alongside the above as each is built 7. Reporting -> Manual -> deferred within this run's Stage 2 scope -> low detail in the source (one bullet: monthly CSV export), lowest business risk to sequence last 8. Security & access -> Manual -> yes -> the row-level tenancy rule is simple and should be modelled from the start, not bolted on 9.
