Same Repo, Two Editors

Is Kiro just a plugin in VS Code?

No — it's a separate application. But it's built on VS Code, so for a developer on one of our projects the difference is close to nothing.

Kiro is a standalone IDE forked from the open-source VS Code codebase. Same window, same file tree, same terminal, same extension model. You still git clone the same repo, you still get the same folders, you still run bin/init-project.sh and ./mxcli from the same built-in terminal. Nothing about the project layout changes — the only new thing on disk is one pointer file in a .kiro/ folder, sitting next to the CLAUDE.md and .cursorrules that are already there.

The whole picture

Day one, side by side

A dev on VS Code / Claude Code

# once, anywhere
git clone …/mxcli-project-toolkit ~/Mendix/…

# per project
git clone …/my-project && cd my-project
~/Mendix/…/bin/init-project.sh .
~/Mendix/…/bin/wire-agents.sh .

# open it
code .

# work
./mxcli -p App.mpr -c "SHOW MODULES"
./bin/exec.sh mdlsource/01-domain.mdl
~/Mendix/…/bin/gate-check.sh . 5

A dev on Kiro

# once, anywhere
git clone …/mxcli-project-toolkit ~/Mendix/…

# per project
git clone …/my-project && cd my-project
~/Mendix/…/bin/init-project.sh .
~/Mendix/…/bin/wire-agents.sh . --with-kiro

# open it
kiro .

# work — unchanged
./mxcli -p App.mpr -c "SHOW MODULES"
./bin/exec.sh mdlsource/01-domain.mdl
~/Mendix/…/bin/gate-check.sh . 5

Two differences, both on the highlighted lines: one extra flag when wiring the project, and a different command to open the window. Everything else — the clone, the scaffold, the MDL, the gates — is the same text in the same order.

What actually changes

ThingIn Kiro
The applicationA separate download, not a VS Code extension — but a VS Code fork, so it looks and behaves like VS Code
Project folders, git, terminalIdentical. One clone, one layout, one .mpr
init-project.sh, PROJECT.md, the 9 stages, the ✋ gatesIdentical — they're markdown and shell, not editor features
./mxcli, bin/exec.sh, mxbuild, Studio ProIdentical. Kiro never writes to the model any more than Claude Code does
The instruction file the agent readsOne new file: .kiro/steering/mxtk-toolkit.md. A pointer to CLAUDE.md, not a copy of it
Permission to run our scriptsGranted per machine, in the user's home folder — it can't be committed, so each dev grants it once by hand
Extensions / marketplaceOpen VSX, not the Microsoft marketplace — most things are there, a few are not
CostMetered per agent run, on top of whatever the team already pays

The one row that matters for us is the last-but-two: Kiro's run permissions live outside the repository, so we can ship the instructions but not the allowlist. Every developer clicks through it once on their own machine.

How confident is this

The layout, the commands and the toolkit side are certain — they're read from our own scripts. The Kiro side is second-hand: its own site is unreachable from the environment this was written in, so "standalone VS Code fork, Open VSX, home-folder permissions" comes from documentation summaries, not from a session anyone here has run. Fifteen minutes with a real install settles all of it, and that run is what the roadmap entry is waiting on.
