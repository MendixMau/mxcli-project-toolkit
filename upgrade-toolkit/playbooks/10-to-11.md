# Playbook: Mendix 10.x to 11.x (one field comparison, no toolkit run yet)

Evidence so far: the Academy review (internal app, 10.18.1 to 11.15.0 headless on a copy, compared change by change
with the team's own 10.18 to 11.12.2 upgrade; `~/Downloads/Academy Mx11 Upgrade Review (1).html` and its scanner
report `upgrade-report.html`, 2026-10-02). Every blocking fix the CLI run hit, the team made too. F1 triage (E2) adds
29 Mendix 11 Java blockers in kept and own modules. Items AC-n are rows in FEEDBACK.md. A full toolkit run (E2) still
has to turn this into a proven playbook.

## Order

1. 10.x below 10.24: the 10.24 rung first, with its full gate, and that rung STARTS with the pre-convert module pass
   (modules to the newest version that fits the source version, before the convert to 10.24). It is required also
   when the target is 11 (T7-3): without it no module has a pristine "step:" commit, and the post-convert updates are
   refused as local edits (T7: 6 of 8 kept). If it was skipped, pass the triage report (made with `--mxcli-diff`) to stepupdate as
   `--localedits $W/localedits.json` so convertmade.sh can prove the refusals convert-made (T7-12). Mendix 11 refuses a 10.18 project ("not supported");
   the scanner report says nothing about it (AC-1). Mendix 10 download names carry a build number: take the newest
   10.24 build from the download listing (`mxversion.py`, full versions), never a guessed `10.24.x`.
2. Module updates on the 10.24 rung, between the two converts: the 11-ready versions need 10.24 or later, and
   Mendix 11 does not import packages made with older Studio Pro, which localedits and stepupdate need (AC-2).
3. Convert to 11 with `convertcheck.py` after it. Expect a few model errors (Academy: 4), read them from the log.
4. Post-convert module updates, dependency resync, `repair/jarclash.py`, build.

## Behaviour changes to review (build clean, behaviour different)

From the Academy scanner report; each needs a journey or a review, not a build fix:
- REST calls no longer encode URL values automatically (65 call sites on Academy): encode explicitly.
- Published REST services always answer in JSON (12).
- Task queues lose the "system context" option (7).
- Empty versus missing text may behave differently (187 places).
- MendixSSO is deprecated (1 May 2026) and leaves the public Marketplace on 1 Nov 2026: plan SAML or LDAP.

Can wait for Mendix 12: Dojo (classic) widgets break only on the React client, optional until 12 (Academy: 381);
Atlas 4 and Java 21 likewise. Two exceptions, both from batch 1 T7:
- widgets that ship their own React code against the client's React: the legacy Charts (`com.mendix.widget.custom.*`,
  react-redux 5 on legacy context, gone in React 19 = Mendix 11.6) break on the Dojo client too. Blocker row 8;
  `missing_deps.py --target 11.x` lists them as DEPRECATED-11; [widgets](widgets.md).
- Atlas 4 is needed as soon as a required module needs it: WorkflowCommons 4.3+ (notes 4.11.0: "Atlas Core
  compatibility v4.3.7") gave 71 CE6083 on Atlas 3 (T7-25). Take the newest version whose notes keep Atlas 3
  (WorkflowCommons 4.2.0) or plan Atlas 4; release_impact lists the row. The plan step must read this row for every module it targets: choosing from `mxcli marketplace versions` alone picked 4.10.0 (67 CE6083 in the Quality Inspection run, QI-7). 4.2.0 works on Atlas 3 but needs OQL v2 and, on 11.12, its activity-type visibility lists (37 CE0456 in that run) are rebuilt for the new enumeration: re-applying the DESCRIBE MDL through mxcli did not fix CE0456 and risks model corruption, a rebuild of the enumeration references in the BSON did (a repair tool for it is BACKLOG #105).
Upgrade every pluggable widget to its newest version for the target (docs, upgrading 10 to 11: React 19 from 11.6
removes `findDOMNode`; incompatibility does not fail the build).
A widget that calls a removed API (`replacement_check.py` row R35 reads the package JavaScript) with no newer version
(a private or stranded owner) is a BLOCKER, not a list item: plan its replacement at triage (NR2-24).

## Tooling on this path

- MxModelReflection update drops the associations other modules own into it (Academy: 9, from the Excel report and
  text template modules). `idcheck.py --xmod` at triage, step idcheck stops it, the module is kept or replayed by the
  edited-modules route. Never accept it: on a live database it drops their tables on the next deploy.
- mxcli cannot set a microflow parameter to required nor switch "System context tasks", and cannot edit old
  reference selectors: these are Studio Pro steps (or a direct model edit on a copy), list them as manual steps.
- MxBuild 11.15 on Linux (Docker) crashed in the error check until three system libraries were preloaded (a
  bundled graphics library links them). The Academy review does not name them: record the names on the first run.
- 11.x mxbuild runs natively on macOS; runapp picks temurin 21.
- mxcli marketplace login cannot prompt inside Claude Code: log in from a separate terminal; never put the token on
  the command line (it lands in the transcript).
- Two sessions on one project: a second Claude session rewrote the upgrade report mid-run. One session per app.

Record new findings in FEEDBACK.md and update this playbook from the E2 run.

## Target 11.12 LTS (LTS-1)

Default end of the path since 2026-10: 10.24 rung first, then one rung 10.24 to 11.12 at its newest patch (11.12.6 on
2026-10-08; the 11.12.5 notes say "do not upgrade to this version", client-certificate REST calls broken; always re-read the notes). From the 11.12 release notes, check each item at triage:
- 11.12.0: the model API element helpers (`add*()`, `get*()`, `getContainer()`, `delete()`) are removed; an app or
  extension that calls them breaks. Studio Pro on macOS runs on Apple Silicon only (containers are not affected).
- 11.12.5: the SAP HANA JDBC driver is no longer shipped with the runtime; an app on SAP HANA must supply it (`userlib`).
- 11.12.5 known issue: the module update flow does not restore StorageGuids/StableGuids for native mobile, which risks
  data loss on device. On a native mobile app, check the offline entities after every module update in this rung;
  a changed guid is a FAIL, not a warning.
- 11.12.0 known issue: embedded navigation profiles with omitted optional parameters show the fallback page; a journey
  that lands there is a finding.
